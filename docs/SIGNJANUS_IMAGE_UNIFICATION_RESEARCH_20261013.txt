一、先回答当前两个问题

1. 当前方法与 JanusFlow 的关系

共同设计：理解和生成的入口分开；共享语言主干；生成使用连续 VAE latent；理解输出文字；分阶段解冻。

决定性差异：
当前：文本和 masked/已生成 latent slots → mT5 encoder → 条件 c；内层带噪 latent z_t 与扩散时间 t → 独立 MLP → 预测干净 latent x0。每次外层 MAR 计算一次条件，内层 DDIM 多步复用条件。
JanusFlow：文本、生成编码器处理的当前带噪 latent z_t、时间 t → 共享 LLM → 生成解码器 → 速度 v；Euler 更新 z_t，每一步都重新处理当前带噪状态。
当前不是“将全部 JanusFlow 模块缩成手语版本”。它结合了 Janus 的编码解耦思路、MAR/DiffLoss 的连续 token 建模以及 MoMADiff 式手语生成接口。

原版 JanusFlow 使用 rectified flow 的线性插值与速度目标，当前使用 DDPM 前向加噪、x0 MSE 和 DDIM；仅改变 sampler 名字不构成 flow。
原版 JanusFlow 把 REPA 对齐作用于 LLM 内的带噪生成表示，当前统一训练只有 SLT CE 和生成 MSE，尚无该对齐项。
原版 CFG 在速度输出上混合条件和无条件结果；当前在进入非线性 MLP 前混合条件向量。两者一般不等价。
当前还有外层 MAR，JanusFlow 没有这层逐批填 latent 的过程。
训练课程也不完全相同：当前 Stage 1 为生成适配器训练，Stage 2/3 为联合训练；JanusFlow 的统一预训练还混合文本任务。相同的“三阶段”名称不能证明流程完全相同。

2. 可以加入 REPA，而且无需先改成 flow

建议优先实现对扩散 MLP 的中间特征做对齐。它接收带噪 latent 和扩散时间，更接近 REPA 的“从带噪生成表示预测干净语义特征”。
教师：冻结 SLT checkpoint 中的 pose encoder，包括需要的 ST-GCN 与投影；eval 模式、停止梯度。REPA 本身无需额外维护完整 mT5 教师副本。
学生：diffusion_head.py 的 MLP 中间 hidden，加入可训练投影头。当前接口只返回 x0，实施时需提供可选中间特征返回路径。
时间轴：当前 ST-GCN 逐帧输出 T 个特征；KL-VAE 输出 floor(T/4) 个 latent。先裁到相同真实有效长度，以四帧聚合为首个对照方案；后续可以比较与 codec 感受野更贴合的聚合。不能仅因张量长度接近就认为位置已对齐。
mask：聚合教师特征后，按 forward_t2p 的 mask 取对应受监督位置；排除 padding 和不可观测的目标。GT confidence 的位置映射需明确记录。
目标可写为：
L_align = mean_valid [1 - cosine(P(h_gen(z_t,t,c)), stop_gradient(E_pose(x_gt)))]
L_total = w_slt L_slt + w_diff L_diff + lambda_align L_align
这是手语移植方案；P 是新增投影头，教师目标来自 GT pose，而不是文字本身。
推理时不计算教师或对齐损失，不需要 GT pose 语义特征。

条件特征对齐可作为单独消融：将 cond_out_head 输出对齐到教师。它更容易加，但 mT5 当前不读取内层 z_t，所以应称为条件语义对齐，不能直接声称复现原版 REPA 的带噪特征对齐。
Stage 1 可先只训练生成模块与投影，保持现有 mT5 冻结；Stage 2/3 再观察共享主干是否受益。Stage 3 的学生 ST-GCN 即使解冻，也应保留独立冻结教师以减少目标漂移。
可能失败点：SLT 特征过于强调句义、忽略手型；教师的时间窗口与 VAE 不一致；新 loss 或投影梯度压过扩散损失。首轮建议全句/时间对齐，之后再比较手部特征与 body/face 特征。
应记录对齐前后的 SLG 手部 DTW、回译、SLT BLEU 与可视化，不以 cosine 上升代替生成质量证据。
原论文：https://arxiv.org/html/2410.06940v4
JanusFlow 的对应公式及 stop-gradient：https://arxiv.org/html/2411.07975v2

二、当前系统可改进的接口

现有理解：69 个关节及 confidence → 按部位 ST-GCN → pose_proj → mT5 encoder → mT5 decoder。
现有生成：文字 → mT5 encoder 与 masked latent slots → cond_out_head → 512D per-token MLP diffusion → 冻结 KL-VAE decoder → 138D 2D pose。
现有共享：mT5 encoder 参数与联合监督目标。它证明两任务共同训练，尚不等于证明互相提升。
现有评测：置信度遮掩的累计 DTW-MPJPE2D，分 body、双手、face、all，hand 为左右手均值；回译在独立 evaluator。
当前 generate_pose 需要给定长度，尚无 text-to-length predictor。GT 长度实验可以保留，但与预测长度系统的比较应分别呈现。
当前 SLT forward 的标量 loss 含 label smoothing，并截断到 max_length=50。奖励模块若计算原句 likelihood，应读取 logits，使用一致的完整目标 token，排除 padding，明确 EOS 和截断规则，不能把负的平滑 CE 直接称为原文的 reward。
当前 512D latent 的通道混合身体各部位。21 个手关节不能直接对应其中 21 个 latent channel；图像区域奖励的空间映射需要重新设计。
当前生成函数由 no_grad 修饰。它能用于黑盒 rollout，但端到端可微回译训练不能直接沿用这个函数。
当前 DDIM eta=0 的逐步转移是确定的，除随机初始噪声外没有所需的非退化逐步 Gaussian action likelihood。标准连续策略 RL 必须另建随机转移和概率路径，终端零方差步骤也需要处理。

三、最值得读透的路线

A. REPA / JanusFlow：语义教师约束带噪生成表示
优先级 P0。目标是在保持细节生成表示的同时，减少“动作数值接近却没有句义”的问题。最小改动是冻结 pose encoder、添加中间投影与时间对齐 loss。保持旧 x0 扩散和 VAE，用等预算实验隔离新监督的收益。
来源：https://arxiv.org/abs/2410.06940
来源：https://arxiv.org/abs/2411.07975

B. RecA：用理解 embeddings 条件重建
优先级 P0。原文用理解编码器的密集表示替代稀疏 caption 来重建输入，针对共享参数的模型保留理解 loss。
手语移植：pose → ST-GCN 语义 tokens → 共享 mT5 与生成头 → 重建同一 pose。它可以检验“SLT 的表示是否保留了生成需要的动作细节”。当前 _encoder_cond 只有文本入口，需增加受控的语义条件入口。
它和 REPA 不同：REPA 给生成 hidden 一个教师目标；RecA 用教师 embeddings 作为重建条件。重建阶段推理可看 GT pose，但正常文本生成评测不能把 GT embeddings 放进条件。
RecA 是监督/自监督后训练，不是 RL。保留文本生成训练或比较原文的顺序课程，避免仅学会复制输入。
原文最新版本还讨论了混合训练的稳定性、训练数据分布与模板近似泄漏；不能只引用最佳分数而忽略数据。
来源：https://arxiv.org/html/2509.07295v4

C. GvU 与 Read It Back / SpectraReward：把 SLT 变成语义 reward
优先级 P0。GvU 将原始 prompt 的 token 概率几何均值聚合为 reward；Read It Back 使用平均 log-likelihood。两者均可用 teacher-forced forward 得到。几何均值与平均 logprob 在固定文本的候选排序上单调对应，但用于组内 advantage 时分值尺度不同，必须作为两个变体比较。
手语移植：
r_sem(y,x_gen) = (1/N) sum_j log p_frozen_SLT(y_j | x_gen,y_<j)
对同一句生成多个候选 pose，用冻结 SLT 快照打分。先检验排序能力，再做策略优化。
优点：不需要先额外标注大规模手语偏好；比逐句 BLEU 更密集；可以检查某些 token 的置信度。
局限：token reward 不提供 token→动作时间段的可靠对齐；它也可能更多反映语言先验。仅提高 SLT 自己对生成 pose 的信心不证明动作正确。
来源：https://arxiv.org/html/2603.06043v1
来源：https://arxiv.org/html/2607.11886v1
官方代码：https://github.com/matrix0721/GvU
官方代码：https://github.com/huangrh99/AlphaGRPO

D. DDPO / DanceGRPO：当前连续生成的在线 RL 基线
优先级 P0。它们将去噪轨迹视为决策过程；组内多个生成结果得到 reward 后优化策略。迁移时动作是连续 latent 转移，不能把 latent 做 softmax 当作图像 token。
需新建 stochastic rollout、old policy/reference、记录 MAR mask 和上下文、转移 logprob、组优势及策略约束。动作历史在更新时要与采样一致，不能用 GT 的已知 latent 替代真实生成前缀。
外层 MAR 的顺序若与参数无关，可先固定；奖励作用于完整输出，更新内层条件动作。两层策略的分解需明确。
只训生成适配器和 MLP 是较保守的起点；若解冻共享 mT5，保留真实 SLT batch 或其他保持约束。
来源：https://arxiv.org/abs/2305.13301
来源：https://arxiv.org/abs/2505.07818
官方代码：https://github.com/XueZeyue/DanceGRPO

E. Diffusion-DPO：离线偏好对照
优先级 P0。先为同一 caption 生成候选，用独立冻结 SLT 与训练参考 pose 的几何指标构建偏好对，再使用扩散偏好目标。比完整在线 GRPO 的工程路径短，但仍需与当前 DDPM 参数化、MAR 条件一致。
用成对相同前向噪声和时间采样减少偏好 loss 方差；偏好样本的 mask/context 规则要明确。不能套文字 DPO 的精确序列 logprob。
把它报告成离线偏好优化，与在线 RL 分开。比较随机偏好、纯回译、纯手部几何、组合偏好，以定位收益来源。
来源：https://arxiv.org/abs/2311.12908

F. DiffusionNFT 与 DiffusionART：避免常规轨迹 policy gradient 的替代
优先级 P1。NFT 使用正负反馈的前向加噪训练目标，不需要保存整个反向轨迹 likelihood。当前 rollout 可保留，但至少要保存 clean latent、mask/order、对应条件和 reward，并重推 x0 参数化下的目标。普通“负 advantage 乘 MSE”不是 NFT。
NFT 原文以 flow/velocity 公式阐述，其隐式正负预测器由 old 和 current 模型构造。若不改变当前 schedule，应推导对应的 x0/epsilon 参数化、时间权重和约束，而不是复制线性 flow 代码。
ART 用每个 prompt 的 reward 与端点聚合得到改进方向，并施加恢复约束。它刚在 2026-10-08 提交，仓库 10-12 宣布公开。值得复核，但尚无本项目验证。
图像论文的效率倍数仅是其特定模型、reward、采样设置下的结果，不能直接当作手语预期提速。
来源：https://arxiv.org/html/2509.16117v2
来源：https://arxiv.org/html/2610.12572v1
官方代码：https://github.com/NVlabs/DiffusionNFT
官方代码：https://github.com/vanzll/DiffusionART

G. UniMRG：给“生成帮助理解”一条可验证的训练路径
优先级 P0。原文在理解目标之外生成重建、深度和分割。手语可移植为 pose 重建、速度、骨方向或手部结构辅助任务。
这些目标大部分可以从已有 2D 数据计算，不必假装新增真实 3D 信息。候选实现是在共享理解 hidden 上增加训练专用的辅助预测/生成接口，推理时去掉。
现有 pose VAE 不保证能编码速度、角度等新目标；需要独立小头或重新定义表示。不要把衍生量直接送到只见过坐标的 VAE 就称为等价实现。
核心实验：仅加更多 SLT 训练、pose 重建、速度/结构、完整辅助生成，比较 SLT 泛化。若只改善生成而 SLT 不变，不能声称反向增强成立。
来源：https://arxiv.org/html/2601.21406v3
官方代码：https://github.com/Sugewud/UniMRG

H. SRUM：全局和局部奖励的监督加权
优先级 P1。原文冻结理解评估器并缓存全局、区域奖励，再进行奖励加权的 flow 训练及约束。其方法不应被描述为在线 GRPO。
手语局部反馈可以针对手型、位置、动作顺序与非手部表达，但需要有能力检验这些因素的评估器。当前翻译模型不能可靠回答每个关节是否正确。
手部 DTW 可作为训练参考下的局部质量信号；它不能自动在混合 latent 通道中定位 hand region。第一版可使用整条候选的组合 reward，后续再考虑时间 credit 或部位解码分支。
作者仓库 URL 在本次 web 访问返回 404，不能据搜索标题声称完整代码可复现。
来源：https://arxiv.org/html/2510.12784v2

I. UniRL / CoRL / HermesFlow：双任务后训练
优先级 P1。它们提供生成、理解反馈及同源偏好或联合策略优化的先例。当前适合先做真实 SLT 数据保持与可信生成数据回放。
CoRL 的全 AR 图像策略与当前连续动作不同；UniRL 在部分离散表示中使用 straight-through 可微采样，不能当作当前 VAE+no_grad sampler 已支持的梯度路径。
若只训练生成模块，报告理解指导生成；若进一步训练 SLT，并实际提高 SLT，才讨论双向共同优化。
来源：https://arxiv.org/abs/2505.23380
来源：https://arxiv.org/abs/2505.17534
来源：https://arxiv.org/abs/2502.12148

J. Pareto LoRA / 任务专属适配器
优先级 P1。当前 SLT CE 与扩散 MSE 的数值尺度不同，1:1 loss 权重不保证梯度平衡。先测共享层上的两任务梯度和各任务的实际退化，再比较比例调整、LoRA 分工、Pareto 整合。
Pareto LoRA 在 Emu2/CoMM 上研究模态梯度整合。本项目 mT5、ZeRO 优化器和任务定义不同。应有固定权重、简单归一化等对照。
新的梯度审计论文提示：降低 cosine 冲突不必改善最终任务权衡。以 BLEU/DTW 的 Pareto 曲线为结果，梯度指标只作诊断。
来源：https://arxiv.org/abs/2606.17296
来源：https://arxiv.org/abs/2609.38465

四、较大架构改动为何排到后面

1. Show-o2 / BAGEL / SenseNova-U1：重构共享主干的交互与任务分工
可借鉴语义-细节融合、专属变换、共享注意力交互。当前应先证明新增显式交互优于共享 mT5 基线。完整 MoT、原生 pose-space flow 或 mT5 处理每个 z_t 都涉及 checkpoint、算力、训练稳定性变化。
图像文献的结论并不统一：JanusFlow 显示解耦及表示对齐的价值；Transferability 比较中某些共享表示模型的跨任务迁移更强；2026-09 的 synergy 研究强调计算分工与共享知识的结合。不同模型与数据使这些结果不能简化成“共享一定最好”或“解耦一定最好”。
来源：https://arxiv.org/abs/2506.15564
来源：https://arxiv.org/abs/2505.14683
来源：https://arxiv.org/abs/2605.12500
来源：https://arxiv.org/abs/2607.04423
来源：https://arxiv.org/abs/2609.01607

2. RAE / BLIP3-o / UniLiP / TokenFlow / WinTok / UniTok
若当前 VAE 已损失手指细节，优化扩散头不能恢复 codec 没保留的内容。先测 VAE 重建与回译上限，再决定重训语义 codec。
RAE 的手语版可以尝试冻结 ST-GCN 编码器加 pose decoder，但 ST-GCN 对关节做了池化，可能不可逆；“用语义 latent”本身不保证精细手型。
重训 codec 后原 latent 统计与生成 checkpoint 的兼容性不能默认成立。
这些路线适合第二版架构论文，不适合全部混入首轮 RL 消融。
来源：https://arxiv.org/abs/2510.11690
来源：https://arxiv.org/abs/2505.09568
来源：https://arxiv.org/abs/2605.18115

3. T2I-R1 / UniGRPO(2026) / UMM-Reflection
规划与多轮修复有潜力，但需要文本规划任务、pose 条件编辑接口和轨迹数据。现有 SLT decoder 只训练翻译，不具备天然的手语诊断能力。
可以借鉴紧凑可验证规划，而不是先生成冗长自由文本 CoT。多轮 RL 必须给规划文字和动作转移分别提供正确概率。
MMaDA 的 UniGRPO 与 2026 reasoning-driven visual generation 的 UniGRPO 是不同工作，不要只凭算法名字合并实现。

来源：https://arxiv.org/abs/2603.23500

五、建议的训练与实验顺序

阶段 0：建立 codec 和 reward 的可信上限
沿用已有 back_translation_eval.py 的 gt、gt_conf1、vae_recon、gen 模式；验证真实 pose、confidence=1、codec 重建、生成四类输入的回译差异。
冻结 SLT snapshot；对同一句 K 个候选记录平均 logprob、几何误差与人工抽检。加入错配 caption、时间顺序扰动等负例，但确认负例在手语语义上确实错误。
检查 reward 是否区分真实动作、坏动作和空/随机动作，防止只奖励语言先验。
对奖励的词级细节、完整句覆盖、confidence 分布和教师输入坐标裁剪进行统一。生成 conf=1 与训练 confidence 不同，应保留 gt_conf1 对照。

阶段 1：最小监督改动
E0 现有联合训练。
E1 等训练预算的继续联合训练。
E2 扩散中间 REPA。
E3 条件 feature alignment（与 E2 区分）。
E4 RecA 条件重建。
E5 E2 + E4（在单项有效后再组合）。
保持 codec、数据、推理步数、长度规则和总训练预算一致。额外 pose 数据若用于重建，给对照相同数据访问量。

阶段 2：离线偏好
同一 caption 生成候选，构建 pure semantic、pure geometry、semantic+hand 等偏好设置，训练 Diffusion-DPO 基线。
先给出候选排序改善的证据，再做偏好优化。Best-of-N 的开销和收益单列，不能和单样本生成直接混报。
测试时排序只能使用实际可用的 caption 和冻结 reward；参考 GT pose 的排序应标为 oracle diagnostic。

阶段 3：连续 online RL
DDPO/DanceGRPO 路线要求 stochastic rollout 和正确 transition logprob。
NFT 路线可以省去反向 likelihood，但仍需推导当前参数化和 MAR 条件下的正负目标。
首轮可使用小组候选数和短采样日程，之后核查与正式采样的质量差异；不能据图像仓库的 GPU 设置推出本项目显存或耗时。
优先更新生成适配器、MLP 和新增投影。逐步评估解冻共享 mT5，并保留真实 SLT 监督。
维持不同奖励分量的日志，保存参考策略和 reward snapshot。reward 分数上升不作为独立成功标准。

阶段 4：证明生成帮助翻译
引入 UniMRG 式辅助结构监督，或仅回放独立教师筛出的生成样本。
比较 SLT-only、joint、joint+alignment、joint+RL、joint+reverse-supervision。
若预算允许，至少多个随机种子并报告波动；单次 smoke 不构成论文结论。

六、奖励组合：手语迁移提案

基础语义：
r_sem = mean_token log p_frozen_SLT(caption | generated_pose)
它来自 GvU/Read It Back 类思路。

有训练参考 pose 时的几何：
r_hand = - phi(confidence_masked_accumulated_DTW_hand(generated_pose, reference_pose))
phi 可使用明确记录的有界或长度尺度变换，以防长句累计距离压过其他 reward。它只属于训练奖励；正式评测仍报告原始累计 DTW-MPJPE2D，不能悄悄改成路径平均。
原生手部坐标是 wrist-local；手部 DTW 侧重局部形态，手的位置和全身协调仍需 body/腕部等参考。

时序与结构：
r_structure 可检查与训练参考的骨方向、速度范围和异常跳变。不要一味惩罚运动量或高速动作，那会鼓励静止或过度平滑的手语。
2D 骨架约束不能证明真实 3D 物理正确性，也不能替代符号学、手型、口型及语法的评价。

组合候选：
R = a*r_sem + b*r_hand + c*r_structure
先分量实验，再组合。没有 reference 的文本-only prompt 可以使用语义 reward 和无参考质量约束；不要宣称它也有 reference DTW 奖励。
如果使用同一模型的理解分支作为内部 reward，固定快照以减少移动目标，并用独立 SLT judge/人工抽检做外部验证；否则可能出现两分支共同迎合错误评分。
闭环回译本身并非新的图像领域贡献。手语研究需要围绕置信度、局部手型、时间对齐与真实双向收益提出有实验支持的区别。

七、评估和贡献的边界

验证理解→生成：冻结生成 codec，在等预算下仅增加理解相关监督，测手部 DTW、回译、质量与多样性。
验证生成→理解：只增加生成/重建辅助目标，测真实手语的 SLT，并和额外 SLT 训练对照。
证明共享有用：独立两个模型、同样数据访问量的联合基线、显式对齐模型对比。
证明 RL 有用：继续 SFT、Best-of-N、离线偏好、在线 RL 不能混成一个增益。
证明 reward 有效：语义、局部手部、时序分量消融；用未参与优化的 evaluator 检验。
保持各数据集分开：How2Sign 和 OpenASL 都应有独立结果及适用的消融，而不是只在一个数据集论证组件、在另一个只列最终分数。
当前代码按用户要求使用 test 选模。调研保持该设置，不改数据划分；这样的结果应明确标注选模协议。论文若需要独立泛化结论，终评集合须未参与 reward 拟合或 checkpoint 选择。
当前生成采用给定/GT 长度。若对照使用预测长度，应分开报告该条件。
当前 hand DTW 是原生归一化 2D 坐标的累计误差，与毫米 3D MPJPE、路径平均 DTW 或图像论文指标都不同。
本报告提出的实验均未执行，没有声称任何模块已带来 BLEU 或 DTW 增益。

八、可以支持的论文故事

当前已实现的故事：通过理解与重建入口解耦，在共享 mT5 上联合训练手语翻译与连续 latent 生成。
有待实验支持的扩展：
理解分支保留的语义知识，先通过带噪特征对齐帮助生成，再通过冻结理解 reward 指导后训练；
手语专属的手部与时序反馈补充全句语义；
结构生成监督进一步改善真实手语理解。
如果只得到 SLG 增益，就应描述理解指导生成；如果 SLT 和 SLG 都有等预算下的增益，再描述双向增强。
图像统一、表示对齐、自奖励、循环一致性和联合 RL 均已有先例。本项目不能仅凭“SLT+SLG+RL”三个名字就宣称首次或独特。
